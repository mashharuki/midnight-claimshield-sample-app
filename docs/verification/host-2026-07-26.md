# Host reproducibility record — 2026-07-26

## Scope

This record validates the non-Dev-Container README path in a newly created
host clone on macOS arm64. The clone had no existing `node_modules`, build
output, generated reports, or package-manager cache inside the workspace.

The feature changes under verification were still uncommitted, so the clean
clone was created from the current repository and the tracked worktree diff
was applied to it before running the README commands. This is a source
snapshot check; after the changes are committed and pushed, a contributor can
replace the local source with the repository URL in the same `git clone`
command.

## Host environment

- OS / architecture: macOS arm64
- Bun: `1.2.0`, downloaded into an isolated temporary directory for this
  verification; the global Bun installation was not changed
- Compact wrapper: `0.2.0`; selected compiler: `0.30.0`
- Docker Engine: `27.4.0`
- Docker Compose: `2.31.0-desktop.2`

## Executed README path

```bash
git clone <source> midnight-claimshield-sample-app
cd midnight-claimshield-sample-app
bun install --frozen-lockfile
bun run verify:environment
bun run build:app
bun run verify:claimshield-assets
bun run test
bun run test:app
bun run dev -- --host 0.0.0.0
```

## Demo readiness and manual boundary

The runnable host check deliberately does not substitute fabricated wallet
state or secrets for live Midnight actions. To run the six README scenarios,
open the Vite URL, select Preview or PreProd, and connect a Lace account on
the same network. Obtain test DUST from that network's README-linked faucet,
ensure Lace supplies matching Indexer / WebSocket / prover endpoints, and use
separate administrator, applicant A, and applicant B browser profiles. Never
put a recovery phrase, secret key, or private claim payload in shell history,
logs, or this record.
